# 首夜侧翼预防与拐角补墙修复计划

状态：已实现并复核，验证结果见 `HANDOFF.md`。复核补齐了障碍下的完整施工依赖、历史压力过期和墙数上限后的石头预留处理；原有打包工具一并保留。

代码基线：`qwj/baseline`，`0a3c3fd`。工作区已有未提交打包工具，实施时保留。先阅读 `AGENTS.md`、`HANDOFF.md` 和本计划；本计划与旧前线计划冲突时，以这里的修复要求为准。

## 1. 问题与已确认原因

用户观察：首夜敌人已出现侧向分流；第二天仍缺拐角，敌人从拐角进入。没有收到本局原始快照，因此以下是可复现的代码缺陷，不声称已还原本局全部行动。

| 缺陷 | 当前机制 | 修复方向 |
| --- | --- | --- |
| 首日只建正面 | `_plan_walls()` 在侧翼压力为零时跳过侧墙，首日没有上一夜观察 | 增加不依赖历史压力的最小首夜侧翼防线 |
| 正面满 4 格后不补角 | 外拐角属于 `front_face`，受 `front_wall_target_count=4` 一起限制 | 拐角独立分类；普通正面数量不再阻止连接墙 |
| 侧墙可能与正面斜向脱节 | 按单格压力排序，未表达侧墙依赖的连接段 | 按连续墙段规划，并将施工依赖传到执行层 |
| 次日丢失侧翼风险 | 每次夜间快照覆盖 `flank_pressure`，夜末清场会清零 | 分开保存即时压力和上一夜摘要 |

合成复现使用完整基地占地 `x=3..4, y=15..16`，朝东，保持默认 `max_walls=10`：

- 第一天计划只有 `(6,14)..(6,17)` 四格正面墙，侧墙为空。
- 放入这四格已建墙和三座武器，第二天人为设置双侧高压力，计划新增 `(5,13)、(5,18)、(4,13)、(4,18)`，却仍缺 `(6,13)、(6,18)` 两个外拐角。
- 夜间出现一只靠近侧翼的合成机器人时，某侧压力为 `1.5`；夜末空机器人快照将其改成 `0`，次日继续为 `0`。

移动允许八方向、允许相邻障碍间对角穿行。因此仅有斜向相接的两面墙不能当作封闭拐角。这里需要修正几何与调度，不能只提高敌人数阈值或 `max_walls`。

## 2. 目标布局与首日建设

### 2.1 明确墙的类别

在归一化前向、横向坐标中，从完整基地 footprint 的二格外圈推导：

- **正面主体**：朝敌人的边，去掉两个外端角。
- **外拐角**：正面边与两条侧边的交点；独立于正面目标数量。
- **前侧翼**：从拐角沿侧边向基地后方延伸的格子。
- **出口**：保留现有侧后方出口，不因补角把出口关闭。

不要写死世界坐标；左右镜像、非方形地图和贴边基地共用算法。武器仍在蓝圈，墙仍在黄圈；墙和基地均不遮挡弹道。

对上面的标准合成基地，首夜最小目标为 8 格：4 格正面主体、2 格拐角、每侧 1 格连接侧墙。示意仅展示局部，`.` 不代表该格实际一定空闲：

```text
         x=4  x=5  x=6
y=13      +    S    C
y=14      .    .    F
y=15      B    .    F
y=16      B    .    F
y=17      .    .    F
y=18      +    S    C

F 正面主体；C 外拐角；S 首夜侧墙；+ 受压后可延长的位置。
```

这是防止正面与侧墙接头漏格的短折线，不保证机器人不会绕到后方，也不保证机器人必须先攻击墙。

### 2.2 施工次序与资源不足时的行为

保持基地/角色应急、三座基本武器、天黑前回防优先。武器就绪后，首日最小防线优先于普通扩墙和无紧迫依据的墙升级。

正常施工：正面主体从中心向两侧补齐，再补角和短侧墙。每侧按“连接段 → 外拐角 → 侧墙”完成，不先造孤立侧墙。两侧风险相同时，确保两角优先于进一步延长任何一侧；随后各补第一格侧墙。

若已出现某侧高风险或已有脱节侧墙，允许该侧的完整连接段提前施工；不能只提高末端侧墙的分数、跳过连接段。工人可以并行施工，依赖只认可实际已建或本回合已提交的建造动作，行走到工地不等于已建。

首次标准布局的 8 格是资源充足情况下的验收目标。实际不足时：

1. 不超过显式 `max_walls`，不挪用基地/治疗/武器预算，不延迟回防。
2. 按完成一段所需的剩余石头、可达路线和剩余白天行动判断可完成程度；优先完成连续有效段。
3. 记录缺的是石头、施工回合、可达格还是墙数额度；次日保留未完成的必需墙位。
4. 首日预防是持续目标，不能因为 `day_index` 变为第二天就取消。

贴边、障碍或操控位使标准 8 格不可行时，生成合法部分并报告不可完成原因，不挪塔、不强行铺满、不把缺口宣称为封闭。侧后方出口、操控位和工人撤离路径继续逐步验证。

## 3. 次日补角与整夜风险记忆

### 3.1 未完成连接优先修正

- 已有正面墙达到 `front_wall_target_count` 时，缺失拐角仍可进入施工候选。
- 已有侧墙、缺连接角时，先补连接角，再考虑沿侧边向后延伸。
- 缺连接段的升级不自动高于补段；若现存关键墙即将失守，其紧急修复仍可优先。
- 已建、在建、计划墙统一计入需要的全局容量检查，避免局部分类绕过上限。
- 正面、拐角、侧翼均进入维护分类；不得因重新分类漏掉已有墙的修复/升级。

### 3.2 即时压力与夜间摘要分开

在 `DefenseMemory` 增加有界摘要，最多保留当前夜和上一夜：

- 每侧峰值压力、有效受压回合数、最近受压回合。
- 各侧既有的受损信息，以及是否观测到机器人进入防线内侧。内侧事件是穿入风险证据，不凭位置推断唯一入口。
- 夜间样本是否完整；漏帧或缺失字段不能记成可靠的“无威胁”。

规则：同回合不重复累计；夜末清场只清即时压力，不抹掉本夜峰值；转入白天后保留上一夜摘要用于施工；新夜开始新摘要；新对局/基地签名变化清空。

只将相邻真实观测累计为受压回合，不用回合差补造漏掉的样本。若直接跨过昼夜边界，用观测所属游戏日转换，不能要求恰好收到边界回合。旧摘要最多服务下一白天，长期缺数据明确标为陈旧，避免永久扩墙。

**夜间放人、清场判断仍使用即时机器人和已提交火力。** 上一夜建设记忆不得让清场后的角色失去安全采集生存物资的机会。

## 4. 实施接口与文件

避免大规模重构，扩展现有模块即可：

| 文件 | 修改内容 |
| --- | --- |
| `solution/layout.py` | 提取统一墙位分类；`DefenseLayout` 增加默认值字段 `corner_walls`、`required_wall_sites`；生成连续段和施工依赖；保存夜间摘要；旧位置参数构造保持兼容 |
| `solution/maintenance.py` | 所有类别统一维护；施工任务尊重连接依赖；必需连接与短侧翼不因即时压力为零被过滤；保留预算和应急排序 |
| `solution/economy.py` | 使用同一施工序列及依赖；`_wall_need()` 包含未完成必需防线；采石、留石、售卖根据剩余需求及本回合预留处理 |
| `solution/strategy.py` | 仅在现有调度接点传递新计划；不改武器组成、角色安全释放和任务状态机 |
| `solution/rules.py`、`solution/configuration.py` | 增加预防开关和每侧初始延伸长度；校验类型与范围 |
| 两套 `config/frontline*.json` | 开启首夜预防；保留原墙数上限，显式配置每侧 1 格 |
| `tools/diagnostics/defense_layout.py` | 输出墙类别、必需墙缺口、施工依赖、即时/上一夜压力和退让原因；校验器能发现缺角与断开的必需段 |
| 相关测试和文档 | 固化三项复现、两日动作闭环、配置兼容与真实验证范围 |

建议参数：

- `initial_flank_defense: bool = False`；两套 frontline 配置显式设为 `true`，legacy 不启用。
- `initial_flank_depth: int = 1`，范围 `1..2`，不含角格，拒绝 bool。更长布局暂不作为首日默认。
- 保留 `front_wall_target_count` 的主体目标含义；两角不占该配额，但计入 `max_walls`。
- `max_walls` 小于完整目标时允许启动，按容量降级并输出未完成原因；不要偷偷把上限改大。

几何分类、依赖和施工顺序只有一个来源。`rank_wall_work()` 与 `build_planned_walls()` 不能各自重排出互相矛盾的施工次序。可复用一个就绪候选函数：检查墙位仍需建造、前置格已建/已提交、容量、占位及路线，再交给现有动作验证器。

施工墙段沿外圈连续连接，可用共享边确定连接顺序；这是墙段结构约束。角色与机器人寻路验证始终使用八方向，不能借此重新引入“禁止对角穿行”。

## 5. 测试、实施顺序与验收

先将以下输入保存为原创合成测试，再实现修复；不需要复制整局真实日志：

| 场景 | 必须验证的行为 |
| --- | --- |
| 首日零机器人 | 前线配置仍计划正面、两角和每侧第一格；不是只有四格正面 |
| 四格正面已建、双侧高压力 | 两角进入候选并在脱节侧墙或侧翼延长前完成 |
| 侧墙已建但角缺失 | 次日不受正面数量阈值阻止，发出实际补角动作 |
| 夜间受压 → 清场 → 次日 | 即时压力为零，上一夜受压摘要仍在；次日补墙，夜间安全采集不受历史压力误锁 |
| 八方向穿角 | 标准最小场景中复现经缺角进入的具体路径；补角后该局部入口不可用。允许绕到后方出口，不能把全图不可达作为验收条件 |
| 左右镜像 | 分类、两角、初始短侧翼及实际建造位置归一化后对应 |
| 地图贴边/障碍/短射程武器 | 合法退让，操控、移动出口和火力覆盖均保留 |
| 额度或时间不足 | 不超 `max_walls`、不透支石头/金币、不延误回防，未完成需求跨日保留 |
| 同回合两工人 | 不重复建造、不把移动当完成依赖、不抢同一目的格 |
| 夜间摘要生命周期 | 重复回合、跳回合、缺字段、日夜跳转、新局重置、陈旧摘要均符合规则 |
| 旧配置和维护回归 | legacy 行为、原有预算/失败恢复、三类墙维护、墙与基地不挡弹道继续正确 |

实施顺序：

1. 先加首日空侧墙、次日缺角、夜末清零的三个失败测试。
2. 修分类与连续段依赖，贯通布局、维护候选和实际施工；随后加首日预防。
3. 保存夜间摘要，并验证它不会改变夜间清场放人的依据。
4. 扩充经济转换测试：从第一天到第二夜前，跟踪 BUILD 指令和成功反馈。资源充足场景要求首夜前完成最小防线；不足场景要求明确退让及次日续建。
5. 跑完整测试、两套配置的双边诊断和解包 HTTP 检查；更新文档，生成新的 frontline 包及 SHA256。

预计代码修复前现有完整测试为 145 项；以实施时实际结果为准。两日经济转换不能模拟真实拥挤和仇恨，局部路径测试不能证明整体胜率。

```bash
make test PYTHON=python3.11
python3.11 tools/diagnostics/defense_layout.py --config config/frontline.json --scenario left --verify
python3.11 tools/diagnostics/defense_layout.py --config config/frontline.json --scenario right --verify
python3.11 tools/diagnostics/defense_layout.py --config config/frontline-balanced.json --scenario left --verify
python3.11 tools/diagnostics/defense_layout.py --config config/frontline-balanced.json --scenario right --verify
python3.11 tools/package_submission.py --config frontline
```

实战复核重点：第一夜前实际完成的墙位、两角是否连上、第二天第一批施工是否补缺口、两夜的侧翼穿入与基地受损、额外采石行动和回防延误。尽量同地图双边对照，不能用单局胜负判定修复效果。
