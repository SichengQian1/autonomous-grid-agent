# v0.10 工人、任务与防御逻辑

本文描述实现，不代表已经提高平台得分或胜率。配置仍在 `solution/rules.py`。

## 布局与开火

默认三座火箭。用面向前方的 4×4 图编号，基地占 6、7、10、11，
火箭占 12、14、15；16 号格控制 12/15，14 后一格控制 14。
后侧外圈中间四格不建墙，完整布局共十六面墙。双方通过同一个坐标变换使用此布局。
异常边缘地图使用合法格回退，不假装不存在的格子可用。

正常三火箭布局用两名角色，按实际路径和可用岗位分配。一个角色每回合只能操作
一炮；共用控制者的两炮按真实冷却错峰。没有第三名角色同时操作三炮的假设。
混合武器或不兼容布局仍使用独立控制者回退。

导弹按预计剩余血量逐枚、逐炮分配，优先消除小中型集群并减少溢出伤害。
迫近残血基地的大型威胁保留紧急优先权。预测伤害不是实际结算证明。

## 白天三人分工

- 建造工人：就近建三炮，分批采石补墙，再参加采购/采卖。已有送货或随身物品
  仍可优先处理；十石是批量，不是只建十墙的承诺。
- 经济工人：在己方半图比较完整采卖路线收益，默认十块一批，凑够关键升级等
  情况提前变现。有重要采购且先锋未承担时，由空闲、距商店近的工人接手。
- 先锋：第一天任务优先；第二天起无活动任务时先考虑有资金的采购，再接下一题。
  正在做题时不会被采购拉走。

武器升级默认全部二级，再全部三级；商店供应和当前背包决定实际购买。
之后考虑基地和墙。危急维修仍可使用应急资金，不能用升级顺序掩盖立即破防风险。
最多三项目的购物单来不及时，尝试缩为最重要的一项。

武器券买后随身携带，恢复经营；顺路已相邻时可用，或者回防到炮旁再用。
携带武器券的早期自由矿工也会回防送券，避免把升级钱留在野外。
炮旁使用武器券优先于该角色当回合开火，且先升完低等级炮。
回防按实际路径加两回合余量，逐人锁定；这比旧余量更紧，需实战观察迟到与堵路。

## 夜间

前两晚，两人守炮，释放的工人可以采卖；靠近机器人的矿点不选，角色受到迫近
威胁时退回后方。场上只剩先锋空闲时，不能把他当工人采矿。

第三晚起，自由角色有墙物品则在 2 号前墙后方待命。墙顺序为 3、4、2、1，
低血线结合估计两回合来袭伤害决定升级/修复；默认回血阈值为估计满血的 40%。
2 号墙后的站位够不到 4 号墙，维护它必须实际移动到相邻格。
没有物品、危墙低于约 20% 血量或来不及保护时撤到后方，不能原地等死。
这些阈值与伤害预测需平台校准。

冷却炮手可在不与本回合开火冲突时使用附近物品。己方威胁清除后恢复任务和经营。
默认仍不召唤、不跨图攻击、不拆墙开关门。

## 两类任务流程

类别由任务点位置/类型识别，不依赖任务数组顺序。题内状态与同局系列方法分开。
先从当前文档明确的提交 JSON、JSON Schema 或字段类型表提取契约；相互冲突时请求
澄清。缺契约的方案保留，只请求补齐契约，最多三次同类拒绝，不无限空转。

API 题：读取当前要求，由模型绑定服务、认证、字段、筛选和分页方式；确定性执行器
请求、去重、核对过滤条件、总数或明确结束标志，再计算答案。短页本身不证明结束。
年代需明确数值、顺序表或题面支持的解析规则，不默认字符串比较。
取数证据、逐字段方法和格式错误进入诊断。HTTP 200 后的请求头、方法与请求体在
本题保留，修改数据路径不会无意替换它们；证据要求改变时可明确 reset_request。
响应中只有一个候选记录数组且筛选通过时，可修正嵌套数组路径；歧义时仍需重新绑定。
普通 Python 的自检不能代替取数证据，该类候选不会据此快速提交为“已验证”。当前题相同请求绑定的完整数据可在
沙箱缓存用于重新计算；缓存不存在就重新请求，不假定文件跨题保留。

修复题：区分文档目录和项目目录，用文件存在性确认；缺路径时做有界唯一文件名
定位。检查替换匹配数，执行真实项目检查入口，支持本地可执行脚本与 JSON/文本
结果提取。不得改检查器。可识别的脚本解释器/首行换行异常通过显式解释器调用恢复，
不改检查程序内容。相同任务内记录补丁落盘后的内容指纹，检查失败重试时只跳过
确认已应用的补丁；文件变化或新题不继承这个判断。
从当前文档确定提交对象结构，凭证提取与包装分开。成功普通脚本的明确 JSON 或
带字段标签输出也可直接提取并提交，旧输出不能串题。

候选与验证结果分开保存。辅助验证器异常不清空已计算且格式完整的候选，临近
截止可据此争取部分分；明确业务断言不成立时不会自动把该候选当作已验证答案。
未知字段不填零、不猜值。内部检查通过仍不等于平台完整通过。

方法经验有 observed、executed、platform_full 三档；部分奖励不能升级到最后一档。
下一题重新绑定对象、认证、项目路径、补丁值和检查调用；兼容合同核对后才合并
先前的分页/聚合或结果提取模板，执行结果矛盾时失效回退。旧答案、凭证和会话
不复用，新对局清空经验。普通脚本路径也保存不含源码、凭证和补丁值的流程经验，
后续相同契约的凭证提取可以实际复用。API 自动复用要求新绑定和当前字段映射齐全，
不能把输出结构相同当作业务语义一定相同。合成复用成功不代表真实模型已稳定使用。

## 诊断

`AGLOG2` 新增独立任务事件，每题有匿名编号、类别/题次、阶段、调用计数、执行
摘要、错误、提交结构、净任务金币与平台结果。金币扣除同时发生的已确认采卖/
购买/建造；缺价格或结果不确定时标为 unknown。

程序字符串、路径和输出先脱敏，再编码。修复凭证不写日志；输出中的未知词用
同局匿名指纹替代。路径匿名化保留层级。原始日志只供本地分析，不进入仓库/包。
每事件、每题和整局均有上限，保留结算余量，重复错误合并并记录丢弃数量。
新增计划拒绝事件、检查启动 errno/解释器摘要、补丁已应用标志和独立验证器片段。
过大的程序结构明示省略，尽量保住失败原因；成功读文档不再算成任务失败。
程序字面量仍脱敏，并明确标记；不能把日志中的替代值当作原程序数值。

```bash
python tools/diagnostics/decode_match_log.py match.jsonl.xz --tasks
python tools/diagnostics/decode_match_log.py match.log.xz --task-id T002 --detail-limit 24
```

旧日志仍可按类别统计；不存在的旧命令/程序细节不会被补造。
