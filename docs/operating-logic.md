# v0.20 工人、任务、防御与宝藏逻辑

本文说明实际实现；合成回归不能证明实战收益。参数集中在 `solution/rules.py`。

## 归一化布局与炮手

正面在上。墙编号和内部武器编号相互独立：

```text
墙1  墙2  墙3  墙4  墙5  墙6
侧A   1    2    3    4   侧墙
侧墙  5   基地 基地   8   侧墙
侧墙  9   基地 基地  12   侧墙
侧墙 13   火14 火15 火16  侧墙
后角 封墙 封墙 先锋 通道 后角
```

侧 A 是墙 1 向基地后方延伸的紧邻侧墙。两侧用同一坐标关系旋转，不按屏幕方向另写一套。
三炮在 14、15、16；先锋在 15 后方，均相距一格。
第三天起，三炮和普通十六墙阵型形成后，在 14 号炮左下、正下两格增加一级封墙，总数十八面；公共炮位和另一后排格保留。封墙不纳入升级阵型。异常边缘地图保留合法格与独立控制者回退。

用户已确认对方工人不能拆我方墙；两格封闭时阻断从后方步行进入修墙通道。正常通行在白天逐回合执行“拆自己的墙—穿过—补回”，每次重建消耗一石，拆墙不计回收。两名工人可同时接近，但每次只让一人穿过并封回；第十晚助手适用同一流程，回程额外留出排队时间。附近可见敌人时不开门，不在被占格上重建，连续无进展会停止重试并重新评估。初次封口不得圈住无重开能力的角色。
正常进出必须给白天封回留足时间。实际暴露时仍保留紧急撤离；夜间无法重建，紧急拆开的缺口待白天恢复。封口不能驱逐已经进入通道的敌人，也不替代墙被机器人摧毁后的防御处理。

夜间先锋一人轮流开火，读取每炮冷却，一个角色每回合只操作一炮。
实际冷却为观察到的四回合发射间隔时形成 ABC—；冷却改变时不强制空等。
保留逐枚范围伤害、预计剩余血量和小中型集群优先，迫近基地的大型威胁仍可优先。
第三晚起，仅夜晚前十回合，三级火箭优先对方归属的小中型机器人；目标已清空、超出射程或尚未三级的炮继续打本方威胁。
对方归属读取 targetTeam，不猜未知值。基地进入接触范围或墙预计两回合内倒塌时取消抢分，回到本方防御。
这是待实战比较的试验；保守估算不代表真实下一步攻击目标。
炮手普通围墙维护交给工人。角色升级武器与开火互斥；有随身武器券时仍可用升级回血。

夜间宝藏出发前替补先抵达后排接应格，先锋让出公共位，替补真正站到公共位后才允许
先锋离开。两个移动步骤不能假设同时占用一个格子，期间留在炮旁的人负责可覆盖的炮。
返回时反向交接。冷却、移动和岗位过渡可能减少一两次射击，日志记录原因；不能声称零损失。
先锋死亡或路径反复受阻时也选工人接替。所有角色死亡或路线彻底隔断无法保证守炮。

## 工人经营与安全

工程工人身份稳定，保留先三炮、批量采石、逐面补墙和补缺口流程。工程工人同时是夜间支援工人，存活期间身份固定；死亡后根据存活状态、位置和墙物资交接。
通常只有工程工人承担建墙采石和墙物资采购，另一工人开局直接采收入矿。建设完成后工程工人也采矿。

前两晚无其他必要职责时，两名工人继续采矿。第三晚起有己方威胁时只留一名支援；
主矿工继续安全生产。己方波次清空后释放支援参加经营。
第十天是例外：经济工人按购物与返回路程提前买最多 5 张维修卷，当晚不再采矿，与工程工人分配不同墙位。
工程工人的必要库存先留钱；资金或容量不足不强买。宝藏替补守炮优先于第二支援。
白天所有工人都按实际回程及时停工。炮手回炮位，工程支援回前排岗位，普通矿工回基地后方空位，避让公共炮位。
普通矿工的回程不以携带武器券为条件；前两晚也先离开远矿，入夜后再根据可见威胁判断能否恢复安全经营。
实际路径外普通余量两回合，购买和使用动作另计；先锋回防计入待用武器券的升级动作。

矿点比较采矿、出售、必要返回整趟的实际路径、批量、库存、容量和价格；对同矿争抢折价，
原目标收益接近时不换矿。取消半场硬过滤，白天两侧资源都可参与比较；工程工人保留石头目标提高到 7，使用后尽量补足；第十天助手同样备石并保留，通行重建会消耗库存。
白昼不把刷新区永久禁采，但新差事必须留出实际回家路程、操作及交通余量。没有能完成的收益行程时回后方待命。
采集和卖矿分阶段：今日采集与必要回防能完成即可开工，出售可延后；商人被威胁覆盖不自动禁止安全矿点生产。
第二天仅主矿工优先采官方新闻支持的涨价或即将停采矿种；工程工人继续比较整趟收益。
停采导致稀缺是抢采依据，不等于已知涨价幅度；无有效依据则照常选矿，第三天取消这一专门优先级。
夜间用所有可见机器人的射程、距离和观测移动扩张危险区，选点和实际移动都避开该区域。
已经暴露时有界搜索撤离路线，允许第一步距离不增加而后续能脱离；只发合法相邻移动，逐回合重新评估。
四周被占满时不伪造逃生指令；提前回防才是主要保护。没有精确敌方寻路预测。
工人已在商店邻格且防御预算充足时可顺手备最多两瓶 Medicine，不为备药专程绕路。
安全且无更高优先级职责时，血量不高于 140 用药；暴露时优先撤离，无路可走且低血量才用药，不把药当成无敌。
一次夜间经营失败仅暂停该角色三回合，再失败延长；同夜三次失败暂停该角色至次日，
不把一个矿点失败解释成全体角色整局都不能夜间经营。

前两天出售矿默认囤积，十块一批、顺路到商人、普通高阶升级缺钱均不触发出售。
第三天起按当前真实价格恢复正常批量采卖；不固定铁矿价格，也不因未经证实预期继续囤货。
官方消息分别记录矿种、限制/涨价/恢复窗口与证据。可靠预告用于路线收益，当前成交仍用运行时价。

提前出售只有两类有记录的例外：必要基础防御的实际资金缺口/生存危机；或用户授权的
满背包生产例外。前者按缺口和实际单价卖最少单位，后者最多卖一个小工作批次，随后恢复囤货。
必要建墙石头不能当普通出售库存，背包满时也不会继续发不可能成功的采石命令。

## 采购与防御时间表

三炮先全部二级，再全部三级。前两天不采购普通三级武器/基地升级，危急回血例外。
基础防御主要使用实际到账的任务资金；不预支尚未完成任务的奖励。
二级三炮、一级基地守第二晚是本轮实战假设，尚未得到验证。

| 截止 | 目标 |
| --- | --- |
| 第二晚 | 三炮二级、必要墙位，基地通常一级 |
| 第三晚 | 资金、路程允许时三炮全部三级；卖矿到账后继续补齐随身券 |
| 第五晚 | 基地二级；墙 2/3 至少一面三级 |
| 第六晚 | 墙 1–5 与侧 A 全三级；墙 6 二级 |
| 后续 | 保持以上阵型；破墙先重建，再恢复相应目标等级 |

武器由实际炮手采购，通常是先锋；普通工人不再代购代送。先锋持券时仍会核对尚缺数量，第三天或后续新收入到账后继续补买剩余券，避免一张券锁死整个采购流程。
工程工人负责的墙升级到期目标不能过滤掉炮手的武器采购选项；未完成的武器发展持续优先于宝藏采购。
先锋白天携券继续工作，
按真实路径和升级动作耗时回防，在入夜使用之前升级。三炮仍先全部二级、再全部三级。
基地到期升级由先锋负责；真实替补到位时才接管炮手职责。

第三天开始优先补到至少 5 张修补卷，不提前到第二天买；这是采购目标，缺钱、缺容量或回程不足时不能保证瞬间达标。
第三天的初始最低库存仍可提前补齐，不等待所有墙建齐；先卖随身非石头矿，保留石头和道具。第三天资金不足且仍有工作时间时继续经营。
后续白天先经营和重建，按“商人—出售每种矿—商店—分批购买—返回支援位—拆墙进门封回”的整趟实际路程预留时间。出发后锁定这趟补给，不重新去采矿；购买前卖清随身铜、铁，不再让高额库存长期压在背包。回程不足时减少购物并及时返回，缺钱不能保证达到目标。完成补给后在岗等待，顺手采购炸弹仍服从既有防御预算。
第五天起最低目标为 6 张；第六天起，在剩余墙升级卷有保障后用余钱将维修卷补到最多 15 张。
资金顺序保必要二级武器与到期基地、最低维修库存，再保障未完成的三级武器发展；普通墙扩充、宝藏、药品均不得挤占这些预留。

墙卷由工程工人统一购买与使用。完整一级阵型需要 7 张一级卷、6 张二级卷，但每次采购
按当前墙级别、缺失墙位和本人背包扣减，达标后不重复买。缺墙在白天优先重建，重建墙重新纳入升级需求。
本轮保持墙 1–5 与侧 A 三级、墙 6 二级。数量从实际墙级别和背包扣除，绝非每晚重复买一整套。

围墙只在夜间升级、修补。第三晚开始有威胁时工程工人在前排支援：低血量且有对应卷时先升级回血，
否则使用维修卷；不能把“等级目标到期”当成对健康墙使用维修卷的理由。
低血量触发结合估算来敌伤害和赶到步数；维修还要求至少缺失约三成血，减少小损伤修满的浪费。
已选中的救援会持续到抵达处理，不因路程变短、阈值缩小就突然放弃；仍逐回合核对威胁、缺血、库存和工人安全。
无迫近威胁时通常等剩余血量不超过四成。临近升级截止，前一晚尾段使用库存升级卷完成等级目标，
提前量计入剩余升级动作和墙间移动，不沿用旧阵型的固定 16 回合。
不等白天绕路升级，也不无限等待掉血。清场后无到期升级/救援工作则恢复采矿。

维修检查所有存活墙，包括未列入升级阵型的侧墙；升级目标仍保持既定阵型，未计划侧墙只修补。
壁垒救援比较血量、射程内/一步接近的威胁、真实赶路时间与随身物资。
有墙遮挡接近路线且携带维修物资时留在墙后，不仅因落入机器人射程或远处另一面墙危险就后撤。
这是基于墙阻挡移动的估计，不是保证。机器人已绕入、屏障缺失、工人实际掉血，或近墙将破而物资不适用时仍撤退。
救援目标和实际路线避开未受墙保护的危险格，保留赶不及就不送死的判断。
每面墙的伤害是保守暴露估计，可能重复计入同一机器人，不是官方下一步攻击目标。

## 防御完成后的炸弹试验

第五天起，三炮三级、基地至少二级且不处于危急低血量，工程工人补齐当天墙卷与维修库存后，
在白天采购路线上用余钱备 Bomb。尚未使用的墙升级卷计入库存，不强迫健康墙提前升级。
不用等夜间看到机器人再去商店；不派经济工人跨程购物。使用当前商店价格、容量和返回路程，普通夜晚最多一枚。
第十天在工程库存、经济工人最多 5 张维修卷及必要应急资金预留后，用可用余钱尽量备弹；当晚允许多次使用。
购买失败或未知反馈当天不重复买，使用失败或反馈不明当晚停止，防止循环浪费。

夜间先判断救墙和撤退；仅无需立即救墙的待命动作可以换成投弹，不占先锋开炮动作。
选当前至少两只预计可击杀的对方中型机器人组成的 3×3 区域，读取 targetTeam，未知归属不猜。
先扣除本回合炮火预计伤害，避免把炸弹投给已预计被炮击杀的目标。伤害及行动顺序仍需实战校准。
Bomb 无投掷距离限制，守墙者不必走到对方半场。持有后不因已经用过几张维修卷而自动禁用。
记录购买条件、保留资金、目标估算、动作反馈；动作成功不能单独证明实际抢分数。

## 宝藏：模型判断、最小校验与平台反馈

保留 v0.17 的模型判断和最小校验。自进化任务、官方新闻与传闻保持独立通道；v0.19 只延后材料采购并提高武器资金优先级，保留既有出发、接炮与失败恢复。
模型负责从中文语义推断任务用品、各自数量、祭坛位置与开放窗口，也由模型处理更正、矛盾、模糊方位。
程序不再查引文子串、分句数量锚点、坐标推导或日期正则，不使用自报置信度与材料证据等级作为门槛。

传闻按首次收到的来源日累积原文，重复广播去重，跨天持续广播不重置来源日。每个已观察到的天保留一个键，
每天最多 6000 字符，超出部分明确记录截断与省略数量；最长十天，文本最多 60000 字符。
每次宝藏请求发送全部已存天数，不再分段挑选旧线索或要求模型 lookup；另有当前天、当前地图尺寸、
货架名称/价格/描述、已接受候选、结构错误以及平台失败记录。传闻保留的是有上限的原文，不声称未截断内容可恢复。

当前货架提供描述时优先使用；没有描述时，已知任务用品附公开属性的简短中性摘要，未知新品描述仍为空。
属性表只用于理解物品，不提供固定配方、数量、位置或日期；货架外的物品不会因此获得购买资格。
货架提示最多 128 项、每项描述最多 1000 字符，省略数量进入提示与日志。价格改变不重复调用语义分析。
相对日期按传闻来源日换算，坐标方向在提示中说明；地图尺寸始终读取本局输入。

模型输出顶层 request_id、mode、materials、location、window。程序只检查：
- JSON 与请求编号匹配；错误允许同一快照一次额外恢复，仍受每日三次额度约束。
- 物品名存在于当前货架，数量是 1～40 的整数，bool 不算整数；非法条目剔除，其他合法条目保留。
- 同名条目保留第一条、后续条目记结构错误；不将重复条目悄悄加成更多物品。
- 坐标为地图范围内整数；窗口在第 1～10 天，结束不早于开始，阶段为 any/day/night。

有效字段替换旧值，缺省或 null 保留旧值；非空材料列表表示新的完整材料集合，不与旧列表自动合并。
materials:[] 清空材料；mode:none 清空全部候选；unknown 保留已有内容，但不采购材料或出发开启。非法坐标/窗口清空对应字段，
避免沿用被模型试图修改的旧位置或日期。目录变化导致已有物品消失时清空材料并请求重分析。
结构完整性仅按“有材料、有位置、有窗口”推导；还需模型 mode 为 treasure 才出发开启。
模型必须自行判断语义是否完整；程序不能保证语义正确。
新传闻在回复延迟期间到达不会让旧回复失效；请求编号仍须一致，后续继续分析新信息。
仅解读官方新闻的回复不能清空宝藏，任务进行时不发宝藏请求，等待回复时不新接会混淆通道的题。

材料、位置和窗口都通过结构校验且模型 mode 为 treasure 后才采购；不完整时继续其他工作。
这是执行时机门槛，不新增跨日证据审计，也不能阻止模型编出结构完整的错误答案。每次分析仍携带所有已保存来源日，
跨日线索的相互印证由原有模型语义流程负责。本版不预留失败后第二套材料的专项资金。
祭品采购默认整局累计上限 300 金，
按运行时价格核算，已通过动作校验的订单保守计入，即使失败或反馈缺失也不退回额度。
这个上限不是固定投入目标；防御资金预留、物品容量、到商店的真实路线和守炮需要照旧优先。
若材料已齐、确定明天白天开放，前一天白天按经济工人实际路程提前安排接炮，整晚由他守炮。
先锋在接班人真正到位后尽早走安全路线，到现场等候，窗口第一回合尝试开启；不提前错误献祭。
路上出现机器人危险时绕行或等安全通路，不为赶第一回合硬闯；因此不能保证所有地图都按时到达。
地点或时间未明确仍不出发；更远的未来窗口不提前多天占住先锋，过期不再采购/开启。
站在祭坛格本身会先走到邻格，再提交开启动作。

整局最多两次实际发出的开启动作。平台返回 2 时记录失败位置/窗口，返回 3 时记录失败材料组合；
失败记录取自当时实际发出的动作对应候选，不误用后来更新的候选。把失败条件传回模型，再分析一次，
禁止原错误组合重复采购/尝试。成功或已被取走后停止宝藏；第二次尝试后不再为宝藏重问或采购。
该流程不保证语义推断成功，仍可能损失祭品和行走时间；采用这一试验方向是用户明确选择。

## 两类任务流程

类别按任务点位置识别，不依赖数组顺序。每题重新读取当前要求和提交结构。
题内数据、凭证和同局方法分开；旧答案和凭证不能用于新题。

API 题先由程序读取当前服务和认证信息，进行有界请求适配。记录数组从实际响应中
定位；已识别的 offset/limit 分页按总数、去重、实际偏移和结束标志取全。
记录不含城市字段时不会编造字段：做一次无效查询对象对照，识别完全忽略查询条件的
服务；无法独立确认筛选的情况明确标记证据等级。HTTP 成功本身不等于查询正确。

当前完整记录保存在题内上下文，模型收到当前要求和实际数据后计算并返回 JSON。
程序先统一直接 JSON、外层 answer JSON 和 answer 内 JSON 字符串，再核对字段类型、
查询对象、数量和可确定的分类集合，及时提交。不能因为缺少包装多问一轮；也不能用
兼容包装绕过真实执行、数据完整性和字段检查。这个路径的候选
有真实取数依据，但不标为逐项独立验证；是否满额仍由平台反馈决定。
比较年代与返回对象名称是两个不同要求，必须按本题语义处理。
数据太大、结构歧义、分页未知或其他变化时保留已有证据，转通用模型/脚本流程。

修复题先定位唯一的当前工程和规范，解析明确的目录、权限、配置行要求；读当前
文件后执行，受任务工作区边界与检查器保护约束。只处理规范引用的项目脚本换行，
不遍历改写整个工程，不改变检查器内容。用真实检查结果驱动最多三轮有界修复。
业务失败、检查启动失败和无凭证分别报告；检查成功且取得当前凭证后立即提交。
规范无法识别、路径有歧义等情况退回现有通用修复能力，不凭历史配置猜测。

一次沙箱流程有总时间和输出限制，正常回合不在服务进程里等待沙箱完成。
已应用补丁的指纹收据、合法脚本调用、当前凭证包装等原有恢复能力继续保留。

同局 API 方法记录认证方式、查询参数、数据路径和分页方式。下一题可以用方法提示
减少首次探索，但认证值、服务绑定、查询对象和记录始终来自当前题。当前响应发生
变化或方法失败就失效回退。复用命中只在实际执行验证后计数；新题清除旧复用标记。
工程修复的固定规范流程每题重新执行，不能把流程名称相同算成运行时自进化收益。
observed/executed 与 platform_full 分开，部分奖励不能证明完整正确。

## 诊断

任务事件记录匿名题号、类别/题次、模型请求/命令编号、阶段、字段契约、实际计划、
执行结果、提交和平台结算。任务金币扣除同回合买卖/建造；缺证据时标为 unknown。

文档、实际程序/方案和模型返回提供可读脱敏片段与分块，保留非敏感字段名、运算和
数值。trace 包含内容指纹、part/parts、长度及截断标记，能够检查是否缺块。
实际执行结果与 command_id 关联；请求与返回通过 request_id 关联。
bootstrap 的固定执行程序由 runner_version 对应到公开实现，日志记录当前绑定与步骤。

answer_received 记录收到的答案包装形式和执行依据，方便区分接收问题与计算问题。
defenseSchedule 记录到期目标、前墙编号/血量/等级/目标等级/射程内伤害估计/一步范围伤害估计，
以及各角色修补卷数量。supportTargets 记录正在继续的墙救援目标；采购和停工原因区分最低库存、变现、回程与无收益行程。surplusBomb/bombResult 记录炸弹门槛、目标估计、等待原因与动作反馈。wallSupply 记录采购等待/资金缺口/路程与库存需求，stoneReserve 记录保留石头。
--operations --day N --role ID 可以从逐回合记录还原采矿、停工原因及购买/使用时间线，
即使详细 operation 事件预算已耗尽也可统计。估计字段不是官方伤害预告。

认证、密码、账号和修复凭证先脱敏再加密。AGLOG3 使用随机 nonce 和认证加密；按用户
确认，解码密钥随公开仓库和提交包发布，所以持有代码的人仍能解密。脚本自动兼容旧
AGLOG2 和新格式，无需额外安装依赖或配置密钥。原始日志只供本地，不进入 Git 或提交包。
每条、每题、整局都有预算，结算保留余量；相同状态但不同程序或失败项不再简单合并。
日志不是无限全量录像：超限明确记录截断/丢弃，分析时不能补造缺失内容。

```bash
python tools/diagnostics/decode_match_log.py match.log.xz --output decoded.jsonl
python tools/diagnostics/decode_match_log.py match.jsonl.xz --tasks
python tools/diagnostics/decode_match_log.py match.log.xz --trace --task-id T002 --detail-limit 128
```

合成通过只证明覆盖范围内的行为，不证明平台分数或胜率提高。
