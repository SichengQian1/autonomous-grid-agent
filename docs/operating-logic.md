# v0.8 工人与任务逻辑

本文描述当前实现，不代表平台上已经达到这些发展目标。

## 每回合先做什么

先解析真实状态、反馈和价格，再检查生存与回防。三人分别按避障路程计算
回防时间，另留七回合安全和交通余量。一人需要回防，不会把其他两人一起叫停。
当天进入回防状态后保持回防；相邻的随身升级券可在不误时的条件下使用。

## 两名工人

| 分工 | 白天主要顺序 | 何时切换 |
| --- | --- | --- |
| 建造工人 | 就近建立三座后排武器，分批采石、建墙，补缺口 | 已持有升级/维修物品时先送货；墙达到布局目标后参加采购或采矿 |
| 经济工人 | 在己方半图选择矿点，采集并出售 | 有采购任务时暂时送货；先锋空闲时优先让先锋接新采购 |

建造工人按开局距离选定，不写死角色编号。当前主配置仍是两座火箭和一座电磁炮。
采石默认每批十块，剩余墙数少时缩小批量；回防时间紧时使用手里已有的石头。
墙按合法区域和通行检查逐步补齐，后方保留固定通道，不拆墙开关门。

经济工人比较整趟“走到矿点、采集、走到商人、出售、回防”的收益和回合数。
默认采十块，但以下情况可以提前卖：背包已满、当前工人自己的库存能凑够下一次升级、
矿点耗尽、继续采不如直接卖，或剩余白天不足以再完成一趟。已经开始出售的
批次尽量卖完再换目标，多个矿种需要分别出售。矿价读取当前商店；明确消息
才能支持等待涨价，且必须先有较完整的防御和周转金。下一项发展升级尚未筹够
资金时不等涨价，先变现。不会把别的工人携带的矿误算成本人这趟的出售收益。

## 先锋与任务

1. 选择可达、未冷却且有明确时限的任务，比较奖励与路程。接取前计入求解
   预计时间和实际回防路程；这仍是估计，不能保证所有题都按时解完。
2. 到任务点后接取，读取题目及相关文件，记录工作目录。
3. 任务进行时先锋保持在任务点，等待 LLM 或命令结果不会被采购逻辑调走。
4. LLM 可以给出 Python 程序、shell 命令、修复并校验的过程，或证据支持的答案。
   程序在独立任务环境执行，保留题目、最近程序和结果，失败后继续修复。
5. 修复题运行实际检查程序，提取 JSON 或唯一匹配的文本结果。普通 Python 求解
   若要直接提交，必须给出答案字段/类型，并在同一次沙箱请求中单独运行验证程序；
   验证断言必须实际执行且引用候选答案。仅正常退出并输出 JSON 不算校验通过。
6. 读取文档会标记是否完整；时间允许时自动补读。文件错误返回工作目录及文件列表，
   已失败而未修正的相同程序不会再次执行，被拒的同一答案也不会反复提交。
7. 命令上限结合任务时限计算，十回合题最多六次、十五回合题最多八次，提交最多三次。
   为交卷预留两回合，临近截止停止补读。最后一回合可提交尚未被拒、字段类型通过
   的实际计算候选以争取部分分；最新执行失败时不使用旧候选。
8. 平台仍报告任务进行时，允许处理预计截止回合到达的结果；结束后清空上下文，
   下一题接取时记住旧输出签名，避免把上题的 LLM 程序用于新题。

执行成功不等于答案正确。新流程减少目录错误、丢失上下文和多一次 LLM 往返，
但答案字段和独立验证程序仍由模型依据题目生成，它们也可能理解错误；代码中
的“checked”只表示这些检查运行通过，不代表比赛判题器已经接受。真实题目的解法质量仍要靠对战验证。无命令输出时不得编造执行结果。

没有可接任务时，先锋可以采购或去商店附近候命；如果任务即将冷却完成，或
整趟采购来不及结束，就不出发。宝藏仍要求线索充分、物品齐备和安全时间窗口。

## 采购、维护与交通

采购使用运行时价格，先明确买什么、送给哪座建筑，再计算完整路线。
默认给下一项基础升级保留资金：第一座二级火箭；第二天起的二级基地；
其余一级武器升级。随后为三面关键前墙二级留钱，第三天起为第一座三级火箭留钱，
第四天起为关键前墙三级留钱，再推进第二座三级火箭；这些日期是可调目标，
不是平台已验证的最优顺序，也不保证当日一定完成。商店没有对应物品时跳过进阶目标。
危墙维修可动用保留资金，并在同趟采购中优先于发展升级；普通修补和额外备件不能
反复耗尽升级储蓄。已经持有的券不重复预留资金。

从第二天起仍以三面前排二级墙为目标，受损墙优先，并结合升级回血；是否在
第二晚前完成取决于收入、必要基础升级和运输时间，不能无条件保证。

一人负责新采购不妨碍其他人送自己已经持有的物品。空闲队友占住目的操作位时，
应让到安全空格；正在做任务、建造或开火的人不会被借走。同回合不抢格、不交换
位置，也不假定队友必定成功移开，因此必要时仍会有一回合等待。

## 夜间

我方威胁未清除时三炮保持控制者，火箭冷却也不离岗。能开火时优先开火；空闲
炮手可在岗位附近使用随身物品。确认我方威胁清除后，恢复任务、采购和采矿；
已有的夜间经济失败反馈仍能关闭相应行为。默认不召唤 Boss、不跨图攻击。

## 如何理解开局等待

角色占着预定建造格时，必须先移开，再由工人下一回合建造。对方移动不可预测、
路径被阻挡、任务仍在执行、任务快刷新或来不及完成一趟经济活动，也可能导致等待。
目标是消除没有用途的长时间停留，而不是让每个人每回合都移动。
